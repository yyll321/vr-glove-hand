# 投放标记与 WA100 全接触震动

场景：`Assets/Underwater/Scenes/UnderwaterRadarSurveyEditable.unity`。

`Delivery Marker - release inside` 是投放计数区域的可见圆盘。抓取和抬升不依赖它。现已隐藏两区圆盘的 Renderer，保留空的区域坐标供原投放计数使用。需要恢复外观时，在该区 `UnderwaterGraspTask` 勾选 `showDeliveryMarker` 并调用 `RefreshDeliveryMarker`，或者停止 Play 后启用圆盘 Renderer 并勾选该选项。无需删除物体。

新增 `Wa100ContactHaptics`，接触后统一向**右手柄**发送反馈：

- WA100 手掌、任意指节与外部实体接触均触发，包括地面、承托台、礁石、海星、鱿鱼和沙层。
- 持续接触重复脉冲，离开接触后停止；无需按住 Grip、移动机械臂或持续发手套命令。
- 默认强度 0.8，持续 0.12 秒，重复间隔 0.18 秒，可在两区 ROV 根对象的 `Wa100ContactHaptics` 中调整。
- 原有运动阻挡仍可以请求脉冲，但与全接触检测共享限频，多个指节接触不会叠加出成倍震动。
- 自身手部/ROV 的内部碰撞不触发，装饰性 trigger 不触发；已抓住并挂在手腕下面的目标仍视为外部接触。
- 沙层碰撞对继续忽略；独立检测可见沙层体积，陷入时仍有反馈，不把沙子变成硬平面。
- 不更改机械臂碰撞、指节驱动、沙层阻力、抓取阈值或原有 3 mm 接触保护。

三个触发来源：各 ArticulationBody 上运行时挂载的 `Wa100ContactRelay` 转发 Collision Enter/Stay；30 Hz 全手物理形状扫描补充静态接触和 4 mm 接触带；原有运动/手指推进阻挡事件复用同一反馈模块。形状扫描也覆盖被 Physics.IgnoreCollision 排除的目标/沙层查询，避免只依赖不会到达的原生回调。

当前 Live Preview 的 `PXR_PTController` 继承 `XRControllerWithRumble`。发送先使用 Input System 的 `SendHapticImpulseCommand` 并记录返回码；失败时尝试 Unity XR 的 `SendHapticImpulse`。不因旧 XR 能力查询没有报告 impulse 就提前放弃，也不调用在 Editor 中无效的 PICO 原生 Android 振动函数。发送返回成功只说明 provider 接受，不能证明控制器电机已动作。

任务面板新增 `RIGHT pulse accepted / REJECTED` 和成功/请求次数。详细接口结果见运行时 `Wa100ContactHaptics.TransportDetails`，如 `PICO Live Preview Controller-Right InputSystem code=1`。

佩戴验证：重新进入 Play，拿着右手柄，让任意 WA100 指节碰台子、海星/鱿鱼，再插入沙层；接触时应有明显重复震动，离开后应停止。若显示 accepted 但手柄仍无震感，需继续检查 Live Preview 至设备的触觉转发、控制器连接/电量及系统振动设置；这与场景是否触发接触应分开诊断。

自动验证：菜单 `Tools/Underwater/Research/29 Verify All Hand Contact Haptics`，或桥接命令 `contactfeedbacksmoke`。用不推动机械手的外部测试碰撞体验证接触/持续接触/退出，验证 Layer 8/10/11/0 接触、沙层忽略碰撞仍触发、自身与 trigger 排除、标记隐藏和真实 provider 返回码。原始结果：`Logs/ContactFeedbackReview/results.json`，归档：`Documentation/CONTACT_FEEDBACK_VALIDATION.json`。测试不冒充真实震感确认。
